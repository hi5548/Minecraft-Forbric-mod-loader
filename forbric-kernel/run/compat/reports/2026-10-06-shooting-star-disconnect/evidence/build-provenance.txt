# Build provenance — the arms, and what isolates them

All builds on this box, JDK 21.0.7 (`/Library/Java/JavaVirtualMachines/jdk-21.jdk`). The game side is not
rebuilt here (the Reborn Energy fixture is absent, so `compileRuntimeJava` is SKIPPED on this machine — the
same limit the sibling lanes recorded), so each boot jar carries the published game side byte for byte.

```
$ ./gradlew --offline -q -Pforbric.stagedRoot=/private/tmp/ss-lane/empty jar   # boot half only
$ python3 /private/tmp/ss-lane/pack.py build/libs/forbric-kernel-0.1.0-SNAPSHOT.jar <published> <out>
```


So the reported pair differs in ONE class added and SIX classes edited, all inside the files `git diff` lists
(the nested `ForbricMergedBaseCompatTransformer$LostSwitchMap` and `ForeignType$1` shift with their owners).
Every other entry is byte-identical — including the whole game side, which neither arm touched.

## Reproducibility

Re-running the boot-half build after the arms were packed produced the same packed sha256 for `after`
(48df3d2b…), so the arm is content-derived, not timestamp-derived.

## Artifact hygiene

429 stale editor/Finder duplicates of the shape `X N.class` sat in `build/classes` (they made the Gradle
`test` task try to execute `…Test 2`). They were deleted before any arm was built; both arms carry 0 such
entries (see each pack.py output line "'X N.class' 0").
